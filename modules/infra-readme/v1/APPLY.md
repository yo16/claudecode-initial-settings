# infra-readme v1

> この文書は Claude Code が読んで実行する導入手順書です。
> 現在のリポジトリに対して、以下の手順を上から順に実行してください。
> 既存のファイルや設定と衝突する場合は、上書きせずユーザーに確認してください。

## 概要

このプロジェクトが使う外部サービス（ホスティング、データベース、認証、CI/CD など）を、ルートの `README.md` の「インフラ」節に一覧で書き、追加、変更、廃止のたびに更新するルールを `.claude/rules/infra-readme.md` に置きます。適用時に、現在使っている外部サービスを調べて節を作ります。

## 前提条件

- 依存する他モジュール: なし

前提条件を満たさない場合は、手順に進まずユーザーに報告してください。

## 手順

### 1. ルールファイルを配置する

`files/infra-readme.md` を、現在のリポジトリの `.claude/rules/infra-readme.md` にコピーしてください。`.claude/rules/` ディレクトリがなければ作成してください。

`.claude/rules/infra-readme.md` が既に存在する場合は上書きせず、既存の内容と `files/infra-readme.md` の差分をユーザーに示して、どうするか確認してください。

### 2. 現在使っている外部サービスを調べる

現在のリポジトリが使っている外部サービスを、次の場所から調べてください。何を外部サービスとして数えるかは、手順 1 で配置したルールファイルの「対象」に従ってください。

- デプロイとホスティングの設定（`vercel.json`、`wrangler.toml`、`netlify.toml`、`fly.toml`、`Dockerfile`、IaC の定義など）
- CI/CD の定義（`.github/workflows/` など）
- 環境変数の例（`.env.example` など）と、コードが読んでいる環境変数の名前
- 依存関係の定義ファイルにある、外部サービスの SDK
- `README.md` と `docs/` 配下の既存の記述

`.env` や `.env.local` など、秘密の値が入っているファイルは読まないでください。

### 3. `README.md` に「インフラ」節を作る

手順 2 の結果に応じて、次のいずれかを行ってください。

- **外部サービスが 1 つ以上見つかり、`README.md` に同じ役割の節がない場合**: ルールファイルの「書く内容」に従って、ルートの `README.md` に「インフラ」節を作ってください。既存の記述は残してください。`README.md` がなければ、リポジトリ名を見出しにして作成してください。
- **外部サービスが 1 つ以上見つかり、`README.md` に同じ役割の節（「インフラ」「構成」「Infrastructure」など）が既にある場合**: その節を書き換えず、ルールファイルの形にした場合の差分をユーザーに示して、どうするか確認してください。
- **外部サービスが 1 つも見つからなかった場合**: `README.md` を変更しないでください。

## 完了条件

適用後、次をすべて確認し、結果をユーザーに報告してください。

- [ ] `.claude/rules/infra-readme.md` が存在し、内容が `files/infra-readme.md` と一致している
- [ ] 手順 2 で外部サービスが見つかった場合、`README.md` の「インフラ」節（または同じ役割の既存の節）に、見つかったサービスがすべて載っている
- [ ] `README.md` に秘密の値（API キー、トークン、パスワード、接続文字列）が書かれていない
- [ ] ユーザーへの報告に、節に載せた外部サービスの一覧（1 つも見つからなかった場合はその旨）を含めている
- [ ] ユーザーへの報告に、ドメインの登録先や DNS のようにリポジトリから読み取れないサービスは載っていないので、使っていれば教えてほしいことを含めている
