# claude-rules 要件定義書

- 作成日: 2026-10-30
- ステータス: ドラフト

## 1. 背景

Claude Code で複数のプロジェクトを運用していると、どのプロジェクトでも共通してやってほしいことが発生する。

- コミットやプッシュなど、日常作業の進め方
- 特定のツールの導入と、その運用方法
- プロジェクト初期に毎回行う手順

これらをユーザーレベルやグローバルレベル（`~/.claude/` 配下）に書くと、更新した時点で稼働中のすべてのプロジェクトに反映される。意図して変える場合はよいが、途中からルールが変わってほしくないプロジェクトもあるため、共通ルールはグローバルには置かず、リポジトリレベルに置きたい。

一方で、リポジトリごとに毎回ゼロから書くのは手間がかかり、書き忘れも起きる。そこで、共通ルールを版付きで一か所に管理し、各リポジトリが必要な版を選んで取り込める仕組みを作る。

## 2. 目的

1. **忘れ防止のガードレール**: プロジェクト開始時に入れ忘れがちなルールや設定を、確実に導入できるようにする
2. **初期手順の自動化**: プロジェクト初期に毎回行う手順を、Claude Code への短い指示で再現できるようにする
3. **版の固定**: 共通ルールを更新しても、既存プロジェクトの挙動が勝手に変わらないようにする

## 3. 非目的

以下は目的としない。過剰な仕組みを作らないための線引きである。

- 組織的な統制やルールの強制。各リポジトリでのルール遵守を保証する仕組みは作らない
- 各リポジトリと配布元との同期の維持。導入後のリポジトリ側の改変は自由とする
- 適用スクリプトやインストーラの開発。適用は Claude Code に手順書を読ませて行う
- Claude Code の plugin やマーケットプレイスの仕組みを使った配布

## 4. 基本方針

| 項目 | 方針 |
|---|---|
| ルールの置き場所 | 各リポジトリ内（`CLAUDE.md`、`.claude/` 配下）。グローバルには置かない |
| 配布元 | 本リポジトリ `claude-rules` |
| 配布元の置き場所 | 利用者が通常使うクローン先。固定パスは定めない |
| 配布元の外に置くもの | なし。本リポジトリに属するものは、本リポジトリの外に一切置かない |
| 管理の単位 | モジュール（関心ごとの単位） |
| 版管理 | モジュールごとに独立した版を持つ |
| 適用方法 | Claude Code に各版の手順書（`APPLY.md`）を読ませて適用する |
| 導入後の扱い | 各リポジトリで必要に応じて自由に改変してよい（通常の運用とみなす） |
| 導入元の記録 | 参考情報として各リポジトリに残す |

## 5. 用語

| 用語 | 意味 |
|---|---|
| 配布元 | 本リポジトリ `claude-rules` |
| 適用先 | 共通ルールを取り込むプロジェクトのリポジトリ |
| モジュール | 関心ごと単位でまとめた共通ルール一式 |
| 版 | モジュールのバージョン（`v1`、`v2`、...） |
| APPLY.md | 各版に含まれる、Claude Code 向けの導入手順書 |
| 導入記録 | 適用先に残す「どのモジュールのどの版を、いつ導入したか」の記録 |

## 6. 機能要件

### 6.1 配布元のディレクトリ構成

```
claude-rules/
  README.md                 # 本リポジトリの説明、モジュール一覧、各モジュールの最新版
  docs/
    requirements.md         # 本書
  templates/
    APPLY.template.md       # 新しい版を作るときの APPLY.md の雛形
  modules/
    <module-name>/
      README.md             # モジュールの概要、版ごとの要約
      v1/
        APPLY.md            # 導入手順書（必須）
        files/              # 適用先に配置するファイル（任意）
      v2/
        APPLY.md
        files/
        CHANGES.md          # 前の版との差分と、上げるときの注意（任意）
```

### 6.2 モジュール

- R-MOD-1: モジュールは関心ごとの単位で分ける。異なる理由で変更されるルールは別のモジュールにする
- R-MOD-2: モジュールは互いに独立して導入できること。依存がある場合は `APPLY.md` の前提条件に明記する
- R-MOD-3: モジュールが扱う対象は `CLAUDE.md` に限らず、`settings.json`、hooks、skills、agents、スラッシュコマンド、初期化コマンドの実行などを含んでよい

### 6.3 版

- R-VER-1: 版はモジュールごとに独立して付ける（あるモジュールが v3 でも、別のモジュールは v1 のままでよい）
- R-VER-2: 版はディレクトリで分ける（`v1/`、`v2/`）。Claude Code が複数の版を並べて読めるようにするため、git タグでの管理は行わない
- R-VER-3: **一度公開した版のディレクトリは書き換えない。** 修正したい場合は新しい版を作る
  - 例外: 誤字の修正など、適用結果が変わらない修正は許容する
- R-VER-4: 版番号は `v1`、`v2` のような単純な連番とする。セマンティックバージョニングは採用しない
- R-VER-5: 各モジュールの `README.md` に、版ごとの一行要約を記載する

### 6.4 APPLY.md（導入手順書）

`APPLY.md` は人ではなく Claude Code が読んで実行する文書として書く。

- R-APP-1: 次の項目を含める
  1. **概要**: このモジュール・版が何を実現するか
  2. **前提条件**: 必要なツールとその版（例: 利用する CLI ツールのバージョン）、依存する他モジュール
  3. **手順**: 配置するファイルと配置先、既存ファイルへの追記・マージ内容、実行するコマンド
  4. **完了条件**: 適用後に確認すべき項目（「そうするとこうなる」の記述）
  5. **導入記録**: 導入記録への追記指示
- R-APP-2: 曖昧な指示（「必要に応じて設定する」など）を避け、適用先ごとに結果がぶれないよう具体的に書く
- R-APP-3: 既存の設定を壊さないこと。`settings.json` などへの追加は、既存の内容を残したまま追記・マージするよう指示する
- R-APP-4: 適用先に既に同じ内容がある場合や、衝突がある場合は、上書きせずユーザーに確認するよう指示する
- R-APP-5: 共通ルールの本文は、適用先の `CLAUDE.md` に直接書き込まず、`.claude/rules/<module-name>.md` に置くことを推奨する。`.claude/rules/` 配下の Markdown は Claude Code が自動で読み込むため、`CLAUDE.md` からの `@` 参照は不要。プロジェクト固有の記述と混ざらないようにするため
- R-APP-6: `APPLY.md` から `files/` 内のファイルを参照するときは、`APPLY.md` のあるディレクトリからの相対パスで書く
- R-APP-7: `APPLY.md` は `templates/APPLY.template.md` の書式に従う（8章参照）

### 6.5 適用フロー

1. 適用先のリポジトリで Claude Code を起動する
2. 手元にある配布元のクローンの `APPLY.md` のパスを指定して、次のように指示する

```
<配布元のクローン>/modules/<module-name>/v1/APPLY.md を読んで、このリポジトリに適用して
```

3. Claude Code が手順を実行し、完了条件を確認して結果を報告する
4. ユーザーが内容を確認し、必要に応じて調整してコミットする

- R-FLOW-1: 適用はモジュール単位で行う。複数モジュールを一度に指示してもよい
- R-FLOW-2: 適用にあたって、ユーザーレベルの設定やコマンドの追加を必須としない
- R-FLOW-3: 配布元のクローンの置き場所を定めない。README や適用例では `<配布元のクローン>` のように置き換えて書き、特定のパスを前提にしない

### 6.6 導入記録

- R-REC-1: 適用先の `.claude/claude-rules-history.txt` に、導入したモジュール・版・日付を一行ずつ追記する
- R-REC-2: 導入記録は Claude Code への指示として読み込まれてはならない。そのため次を守る
  - Claude Code が自動で読み込む場所（`CLAUDE.md`、`.claude/rules/` 配下）には置かない
  - 拡張子を `.md` にせず、ルール文書と見分けがつくようにする
  - `CLAUDE.md` などから `@` で参照しない
  - ファイルの先頭に、指示ではなく記録であることを明記する

```
# claude-rules の導入記録。Claude Code への指示ではない。
module-a@v1 2026-10-30
module-b@v2 2026-10-30
```

- R-REC-3: 導入記録は参考情報であり、適用先の現状が記録どおりであることは保証しない
- R-REC-4: 通常の利用で参照することは想定しない。想定する用途は次の2つ
  - ある版に不具合が見つかったとき、影響を受けるリポジトリを探す手がかりにする
  - 新しい版へ上げるとき、導入元の版と現在のファイルを比べて、ローカルの改変を残したまま更新する手がかりにする

### 6.7 適用先での改変と更新

- R-UPD-1: 適用後のファイルは、各リポジトリで自由に改変してよい。配布元へ反映する義務はない
- R-UPD-2: 新しい版へ上げるのは任意とする。上げる場合も、通常の適用と同じく新しい版の `APPLY.md` を読ませて行う
- R-UPD-3: 版を上げる際の注意事項がある場合は、新しい版の `CHANGES.md` に記載する
- R-UPD-4: 適用先での改変のうち、他のプロジェクトでも使えそうなものは、配布元の新しい版として取り込むことを検討する（任意）

## 7. 非機能要件

- R-NF-1: **軽量であること。** 配布元はほぼ Markdown と、配置用のファイルだけで構成する。ビルドやスクリプトの実行を必要としない
- R-NF-2: **読みやすいこと。** 人が `APPLY.md` を読んでも、何が起きるか分かること
- R-NF-3: **安全であること。** 適用時に既存の設定やファイルを黙って上書き・削除しない
- R-NF-4: **公開して問題ない内容に限ること。** 配布元は GitHub の公開リポジトリとして運用する。トークンや個人のパス、社内情報など、環境固有の値や公開できない情報は置かない
- R-NF-5: **自己完結していること。** 本リポジトリに属するものは、本リポジトリの外に一切置かない。固定パスのクローン、ユーザーレベルの設定（`~/.claude/` 配下）、スラッシュコマンド、シンボリックリンク、環境変数などを前提にしない。仕組みの説明と利用に必要なものは、すべて本リポジトリの中に揃える。時間が経って運用を忘れたころに見返しても、リポジトリの外に正体不明のものが残らないようにするため

## 8. APPLY.md の書式

`templates/APPLY.template.md` の内容は次のとおりとする。新しい版を作るときはこれをコピーして埋める。

````markdown
# <module-name> v<N>

> この文書は Claude Code が読んで実行する導入手順書です。
> 現在のリポジトリに対して、以下の手順を上から順に実行してください。
> 既存のファイルや設定と衝突する場合は、上書きせずユーザーに確認してください。

## 概要

<このモジュール・版を導入すると何が実現するかを 1〜3 文で書く>

## 前提条件

- <必要なツールとバージョン。確認コマンドがあれば併記する>
- <依存する他モジュールがあれば `module@vN` の形で書く。なければ「なし」>

前提条件を満たさない場合は、手順に進まずユーザーに報告してください。

## 手順

### 1. <手順の名前>

<何を、どこに、どうするか。ファイルを置く場合は `files/` からの相対パスと配置先を明記する>

### 2. <手順の名前>

<既存ファイルへの追記やマージの場合は、既存の内容を残すことを明記する>

## 完了条件

適用後、次をすべて確認し、結果をユーザーに報告してください。

- [ ] <確認項目。ファイルの存在、設定の値、コマンドの実行結果など、確認方法が明確なもの>

## 導入記録

`.claude/claude-rules-history.txt` の末尾に次の 1 行を追記してください。ファイルがなければ、先頭行に `# claude-rules の導入記録。Claude Code への指示ではない。` を書いて作成してください。

```
<module-name>@v<N> <今日の日付 YYYY-MM-DD>
```
````
